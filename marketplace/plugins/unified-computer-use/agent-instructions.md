# Codex Autonomous CUA is installed

For browser interaction and native desktop UI, always use this plugin's `autonomous_cua_repl` MCP server and its `js` tool. The tool may appear as `mcp__autonomous_cua_repl.js` or `mcp__autonomous_cua_repl__js`. Use its current `cua` entry points and read the returned first-use documentation. Browser, Chrome, and Computer Use skills still guide the task, but route their UI operations through this shim rather than the bundled `cua_repl` or another automation server. Use the `use-autonomous-cua` skill when selecting a UI tool.

The user installed this plugin to preauthorize routine app/site access. Perform actions already authorized by the user's task without asking again merely because they use a browser, an app, or an upload/download. This does not grant authority for unrelated actions, new disclosures, spending, or external commitments. Preserve normal automatic code review, native policy denials, authentication, CAPTCHA, TCC, and separate audio consent.

Keep purpose-built connectors, APIs, shell commands, and file tools for tasks that do not require UI interaction. This includes supporting local I/O: after an authorized Copy action through the shim, read macOS clipboard text directly with `LC_ALL=en_US.UTF-8 /usr/bin/pbpaste -Prefer txt` through the shell tool. A clipboard read is not a replacement UI runtime. Check that the copy succeeded and the content matches the intended source; the clipboard is shared and can be stale. Do not stage clipboard data through TextEdit, another editor, or a cloud-synced document merely to read or save it. Write directly to the task's intended local destination when saving is requested. See the usage skill for details.

Respect the user's named browser and account. A missing documented capability is different from a policy denial: use an appropriate supported non-UI operation for the missing capability, without inventing a CUA or Sky method. If the shim itself is unavailable or incompatible, use the `update-autonomous-cua` skill when an update is requested, or explain the specific blocker. Do not switch UI runtimes or access paths to evade a denial.

Use the `update-autonomous-cua` skill for “Update Codex Autonomous CUA”, “update no approvals codex”, “update no approvals cua”, and natural variations of those requests. Users can also invoke `$update-autonomous-cua`. Treat “update our shim” as shorthand only when the conversation clearly identifies this plugin.
